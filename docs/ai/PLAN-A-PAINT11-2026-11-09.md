# PLAN A PAINT11 – Simple End: End-Gemälde (W11 / IG31-61), 09.11.2026

Basis claude-wave1, Branch a-paint11, nur 26.3 Fabric.

## Ist-Zustand (26.3 Vanilla)
- `PaintingVariant(width, height, asset_id, title, author)` ist eine Datapack-Registry (`data/<ns>/painting_variant/*.json`); der Platzier-Pool ist das Tag `minecraft:painting_variant/placeable`; Sprite = Atlas `paintings` (Directory-Quelle `painting`, also `assets/<ns>/textures/painting/<id>.png`).
- `Items.PAINTING` ist ein `HangingEntityItem`; `Painting.create` wählt aus dem Tag die größte passende Variante. Drop und Pick-Result sind fest `Items.PAINTING`.
- Vanilla-Mengen (platzierbar): 1x1 8, 2x1 5, 1x2 3, 2x2 7, 4x2 5, 4x4 5, 4x3 2, 3x4 2, 3x3 9 = 46.

## Entscheidung (A12, geringster Eingriff)
- Eigenes Item „End-Gemälde“ (`EndPaintingItem`), das nur das Tag `simpleend:end_paintings` platziert. Vanilla-Gemälde und deren Tag bleiben unberührt (kein Eingriff in Vanilla-Verhalten).
- Gesetzt wird eine normale Vanilla-`Painting`-Entität (keine eigene Entität, keine Netzwerkänderung). Nur ihr Drop/Pick-Result zeigt per Mixin (`PaintingMixin`, nur für `simpleend:`-Varianten) auf das End-Gemälde.
- Animation nur Client: `PaintingRendererMixin` tauscht am Ende von `extractRenderState` die Variante gegen eine Kopie mit Frame-Asset (`<id>_1..4`); Timer je Entität (`EndPaintingAnim`, WeakHashMap), 60–120 s Zufallsabstand, Ablauf 1,2,3,4,4,3,2,1 mit 2 Ticks je Schritt, danach wieder Standbild.
- 46 Motive aus `tools/gen_paintings.py` (11 Themen: Auge, Chorus, Shulker, End-Stadt, Drache, Leere, Sterne, Kristall, Insel, Portal, Enderman; eigene Pixel, kein Mojang-Pixel); Animation je Thema (Lid, Wippen, Deckel, Fenster, Flügel, Wirbel, Sternschnuppe, Puls, Schweben, Augen füllen, Teilchen).
- Rezept: Gemälde + Endstein (formlos) → 1 End-Gemälde, Unlock-Advancement. Lang EN/DE, Fragebogen, Wiki-Note, Test-Zentrale-Truhe, Tab.
