## c) Automatische Übernahme (vorbereitet, NICHT eingeschaltet)

Neuer Befehl `editor_save.py pull` (nur Lesen auf sb-web, keine PATCH):

    python3 tools/textures/editor_save.py pull --git-dir /root/sb.git \
        --remote "ssh -o BatchMode=yes sb-web" --dir /srv/devqueue/textures \
        --base claude-wave1 --report /root/b-fertig.md [--dry-run]

- listet `<dir>/*.json` per `ls`, liest neue Sätze per `cat` (Save-ID wird vor dem Einbau in den Befehl geprüft);
- überspringt: Branch `tex-*-<sid>` existiert schon im Hub, Save-ID steht schon in der Historie von `--base`
  (Handübernahme), state `failed`, bekannte Fehler (Zustandsdatei `--state`, Standard `~/.cache/sb-texpull.json`);
- legt je Satz mit `apply_save` (gleiche Prüfungen wie bisher, PNG = Komposition der Ebenen) den Branch
  `tex-<name>-<sid>` direkt im Hub `/root/sb.git` an (git-Plumbing = „push“, kein Worktree) – Abweichung vom
  Wortlaut „tex-<ts>“: die Save-ID **ist** der Zeitstempel (ms); der Name behält die bestehende Konvention, mit der
  A tex-*-Branches ins Bündel nimmt;
- meldet je neuem Branch eine Zeile in `--report` (`- tex-… <commit> (Basis …) – Editor-Speicherung <id> …`);
- idempotent: zweiter Lauf ohne neue Sätze = keine Änderung, keine Zeile.

**Einschalten (braucht Besitzer-OK, A fragt):** auf sb-agent als root

## d) Editor-Polish

### Malen mit Deckung (source-over auf dem Ebenen-Pixel)
`plot` mischt jetzt: Farbe mit Alpha `sa` über den vorhandenen Ebenen-Pixel – gleiche Ganzzahl-Formel wie
`compose`/normal (`rest = da·(255−sa)/255`, `oa = sa+rest`, Kanal `rnd((cs·sa + cb·rest)/oa)`, Alpha `rnd(oa)`);
`sa = 255` ersetzt wie bisher. Innerhalb eines Strichs zählt jeder Pixel einmal (Punkte entdoppelt, Strich wird
aus dem Ebenen-Stand beim Strichbeginn neu gezeichnet → kein Aufsummieren beim Hin- und Herfahren).
Alpha-Sperre: Farbe wird gemischt (`rnd((cs·sa + cb·(255−sa))/255)`), Alpha bleibt. Farbe mit Alpha 0 löscht
(wie bisher). Füllen nutzt dieselbe Mischung.
Radierer: Stärke = Deckung der Hauptfarbe (`ea`), neues Alpha `rnd(a·(255−ea)/255)` (Farbe bleibt, 0 → Pixel leer);
Deckung 100 % löscht ganz wie bisher.

### Blendmodi je Ebene
IDs (W3C Compositing Level 1 + zwei Photoshop-Modi): `normal, add, subtract, multiply, screen, overlay,
soft-light, hard-light, lighten, darken, difference, hue, saturation, color, luminosity` (DE: Normal, Addieren,
Subtrahieren, Multiplizieren, Negativ multiplizieren, Überlagern, Weiches Licht, Hartes Licht, Aufhellen,
Abdunkeln, Differenz, Farbton, Sättigung, Farbe, Luminanz). `.layers.json`: Feld `blend` je Ebene (fehlend =
normal; alte Dateien unverändert gültig und pixelgleich). Python `validate` + Editor `validate` erlauben die Liste.

**Rechenregeln (in beiden Sprachen wörtlich gleich, IEEE-double, gleiche Reihenfolge):**
- Ebenen von unten nach oben, Hintergrund = bisheriges 8-bit-Ergebnis (`out`), nach jeder Ebene auf 8 bit gerundet
  (`rnd(x) = floor(x+0.5)`), wie bisher.
- `sa = rnd(a·opacity/100)`; `sa ≤ 0` → nichts.
- `normal`: unverändert der bisherige Code (Byte-Gleichheit aller vorhandenen Dateien).
- sonst: `cb = out/255`, `cs = px/255` je Kanal; `B` = Blendfunktion (W3C, s. u.); gemischte Quellfarbe
  `m = (px·(255−da) + B·255·da)/255` (W3C: `Cs' = (1−αb)·Cs + αb·B`); dann source-over:
  `rest = da·(255−sa)/255`, `oa = sa+rest`, Kanal `clamp(rnd((m·sa + cb8·rest)/oa))`, Alpha `rnd(oa)`.
- `add = min(1, cb+cs)`, `subtract = max(0, cb−cs)`, `multiply = cb·cs`, `screen = cb + cs − cb·cs`,
  `hard-light: cs ≤ .5 ? cb·(2·cs) : screen(cb, 2·cs−1)`, `overlay(cb, cs) = hard-light(cs, cb)`,
  `soft-light: cs ≤ .5 ? cb − (1−2·cs)·cb·(1−cb) : cb + (2·cs−1)·(D−cb)`, `D = cb ≤ .25 ? ((16·cb−12)·cb+4)·cb : √cb`,
  `lighten/darken = max/min`, `difference = |cb−cs|`;
  nicht-separabel: `Lum = .3r + .59g + .11b`, `ClipColor`, `SetLum`, `Sat = max−min`,
  `SetSat(C, s)`: jeder Kanal `(c−min)·s/(max−min)` (max = min → 0); `hue = SetLum(SetSat(Cs, Sat(Cb)), Lum(Cb))`,
  `saturation = SetLum(SetSat(Cb, Sat(Cs)), Lum(Cb))`, `color = SetLum(Cs, Lum(Cb))`, `luminosity = SetLum(Cb, Lum(Cs))`.
- `mergeDown`: die untere Ebene behält ihren Modus, die obere wird mit ihrem Modus eingerechnet.

UI (Variante A der Vorschau, funktionsfähig als Platzhalter bis zur Wahl): Auswahlfeld „Modus“ unter dem
Deckkraft-Regler der aktiven Ebene; in der Ebenenzeile ein Kürzel (z. B. „Mult.“), wenn nicht Normal.
Tastenkürzel neu: `Umschalt+O`/`Umschalt+P` blättert den Modus der aktiven Ebene (Undo-fähig).
