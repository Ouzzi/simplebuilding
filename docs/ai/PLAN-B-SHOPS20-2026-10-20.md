# Plan b-shops20 – Shops-Umbau (KONZ20, 20.10.)

Grundlage: `docs/ai/KONZEPT-SHOPS-UMBAU-2026-10-19.md` §7, Besitzer-Wahl KONZ20: S1 A (Ender-Shops), S2 W2 (fern nur
entnehmen, Lieferzeit 2 s/Stapel), S3 d (nur gleiche Dimension, Config), S4 t (Verkaufsblock + Lager nur Transaktionen,
Vitrine bleibt Waren-Eingang), S5 k (Handelskontor / Trade Terminal). Modul `modules/simpleshops`, nur 26.3.

## Ist-Zustand (gelesen)
- Inhalte liegen in drei Block-Entities: `SalesBlockEntity` (Besitzer, `prices` 5, `earnings` 27, `revision`, Sperre),
  `DisplayCaseBlockEntity` (`goods` 5), `SalesStorageBlockEntity` (`earnings` 27). Alle Menüs/`ShopTrade`/`ShopStorage`/Tests
  greifen über `goods()`, `prices()`, `earnings()` auf diese Listen zu.
- `ShopLedger` (SavedData) zählt nur Standorte, `ServerShops` (SavedData) die Server-Shops. Kein Fernzugriff.
- Einnahmen-Slots haben schon `mayPlace = false`; Nebenwege (Zifferntaste, Doppelklick, Drag) sind ungetestet.

## Stufe 1 – Belege + Rezepte (Commit 1)
- Rezepte: Verkaufsblock `PPP/IEI/PCP`, Lager `PPP/IEI/PHP` (E = Enderperle), Advancements unverändert.
- GameTest `no_insert_every_click_type`: Verkaufsblock allein, kombiniert, Lager – PICKUP (links/rechts), QUICK_MOVE aus dem
  Inventar, SWAP (Zifferntasten 0–8 + Nebenhand 40), PICKUP_ALL (Doppelklick), QUICK_CRAFT (Drag, links/rechts/mittel),
  CLONE, THROW; danach Trichter darüber/darunter. Beleg: Einnahmen nie mehr als vorher, Item-Summe gleich. Gegenprobe:
  die Vitrine (StockMenu, kombinierte Waren-Reihe) nimmt Ware an. GameTest `recipes_ender_pearl`.

## Stufe 2 – Ender-Datenhaltung (Commit 2)
- Neu `logic/EnderShops` (SavedData `simpleshops:ender_shops`): `Vault` je Shop-Block (Id `p000001`, nie wiederverwendet),
  Art sales/case/storage, Besitzer, Dimension, Position, Items (27 bzw. 5), Preise, öffentlich, Name, Server-Id,
  Verknüpfungen (Verkaufsblock → Vitrine, Lager), Lieferungen unterwegs. Laufzeit (nie gespeichert): `revision`, Sperre.
- Block-Entities halten nur noch die Id (+ Besitzer/Name für Client-Sync); `goods()/prices()/earnings()` liefern auf dem
  Server die Listen des Eintrags (gleiche API → Menüs, `ShopTrade`, `ShopStorage` bleiben). Client: Spiegel wie bisher.
- Regeln: Abbau droppt den Eintrag einmal am Block und löscht ihn; Block ohne Eintrag oder mit fremder Position
  (kopierte Daten) = neuer leerer Eintrag (kein Dupe); Eintrag ohne Block bleibt (verwaist, nichts verloren),
  `/servershop orphans [clear]` (OP) listet bzw. räumt (droppt nichts, gibt Inhalt dem ausführenden OP).
- Migration: altes BE (Items im NBT, keine Id) zieht beim ersten Server-Zugriff in einen neuen Eintrag; bis dahin speichert
  es seine Items weiter selbst (verlustfrei). Sperre + `revision` wandern in den Eintrag (gleich für vor Ort und fern).
- Tests: Migration alt→neu (Item-Summe gleich, NBT danach ohne Items), kopierte Id → leer, Speichern/Laden-Rundlauf,
  Abbau droppt genau einmal, `/setblock` mit Skip-Side-Effects → verwaist + aufräumbar. Bestehende 52 Tests bleiben grün.

## Stufe 3+4 – Handelskontor (Commits 3, 4)
- Block `simpleshops:trade_terminal` (hält nichts, normal abbaubar), Rezept `GEG/BLB/PPP` (Gold, Enderauge, Bücherregal,
  Lesepult, Bretter). Menü `TradeTerminalMenu` ohne eigene Pakete: Ansichts-Slots (Item mit Name/Lore = Zeileninfo),
  DataSlots, Menü-Knöpfe (`clickMenuButton`); Suche als Zeichen-Knöpfe (≤ 32 Zeichen), Anfrage rate-limitiert (4/s).
- Tab „Meine Shops“: Liste eigener Shops, Auswahl → Einnahmen abholen (nur heraus, nur was ins Inventar passt),
  Preise ändern (gleiche Vorlagen-Klicks), öffentlich/privat, Ware entnehmen (W2: nur öffentlich + Preis, gleiche Dimension,
  Lieferzeit Config `remoteDelaySeconds` 0–20, Standard 2 s je Stapel; Reservierung beim Auftrag, Abbruch legt zurück).
  Name: Amboss-Name des Verkaufsblocks (≤ 24 Zeichen).
- Tab „Shops durchsuchen“: öffentliche Shops aller Spieler + Server-Shops, Suche (Item-Name/Mod-Id), Filter „hat Bestand“,
  Sortierung Preis/Entfernung/Besitzer, Seiten (27 Angebote je Seite ≤ 50). Kauf über denselben `ShopTrade`-Pfad mit
  Zahlplätzen; Sperre wie vor Ort; eigene Shops sichtbar, nicht kaufbar; nur gleiche Dimension (`remoteCrossDimension`).
- Config neu: `remoteStock` (none|take, Standard take), `remoteDelaySeconds`, `remoteCrossDimension`.
- Tests: Fernkauf = Vor-Ort-Kauf (Bilanz), entladener Chunk bleibt entladen, Vor-Ort + fern gleichzeitig (Sperre),
  Lieferzeit + Abbruch/Disconnect legt zurück, privat nicht im Katalog, Dimensionsregel, Rate-Limit, fremde Id/alte
  revision abgelehnt, Einnahmen abholen ohne Hineinlegen, Fuzz (Item-Summe). JUnit Layout wie `ShopLayoutTest`.
- UI: simplelib `UiBoxes`, Palette BARREL, Kontrast ≥ 4,5:1 (Werte im Bericht). Textur: 3 eigene Varianten, Empfehlung
  eingecheckt (vorläufig).

## Risiken
- BE ohne Level (Tests mit `new SalesBlockEntity`) → lokale Liste; Rundlauf-Test wird auf Id-Rundlauf umgestellt.
- Gametests teilen eine Welt: Einträge sammeln sich (je Test wenige, Obergrenze `MAX_VAULTS`).
- Kein Client-Lauf erlaubt (Regel 20.10.) → Client-Abnahme der Tabs bleibt offen.
