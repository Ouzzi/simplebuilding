Stand 2026-09-25 (Branch worktree-agent-ab8768b8d44c3f4cd, nicht gemergt): MC 26.3 fuer Fabric + NeoForge,
Forge bleibt 26.2-only. Versionen: Loader 0.19.5, Fabric API 0.161.0+26.3, NeoForge 26.3.0.16-beta,
Cloth 26.3.159, ModMenu 21.0.0, JEI 31.7.0.37, MDG 2.0.147 (alle NeoForge-Module, ein Plugin pro Build).

**Struktur:** `:mc26_3:fabric`/`:mc26_3:neoforge` kompilieren die 26.2-Baeume + Overlay. Zwillinge:
common/src/mc26_2/java <-> mc26_3/overlay/java (Shim `com.simplebuilding.version.McVersion` u. a.),
src/mc26_2/java <-> mc26_3/fabric/src/main/java (Datagen), *clientgametest*-Paare, neoforge/src/mc26_2/clientGameTest
<-> mc26_3/neoforge/src/clientGameTest. `gradlew checkOverlays` (an check) erzwingt: kein Schatten, jeder hat Zwilling.
Ressourcen: mc26_3/resources.gradle - mergeResources263 baut EINEN Baum je Modul (Vorrang pro Pfad),
checkResources263 (an check) prueft das Ergebnis. FALLE: Loom haengt das Datagen-Ausgabeverzeichnis als erstes
Resourcen-srcDir ein (addToResources=false setzen) - das hat eine falsche EXCLUDE-Reihenfolge im Worktree
versteckt, im Hauptcheckout gewannen dann die 26.2-Dateien (Gate rot, 2026-09-25). mc26_3/generated = nur die von 26.2
abweichenden Datagen-Dateien (syncGenerated263 nach :mc26_3:fabric:runDatagen).

**API-Brueche 26.2 -> 26.3 (am Bytecode belegt):** GLFW weg (SDL, InputConstants.KEY_* haben andere Werte,
isKeyDown(int) ohne Window, Type.KEYSYM -> KEYBOARD); Block-Codecs komplett weg; PushReaction BLOCK/DESTROY/PUSH_ONLY
-> IMMOVEABLE/POPPED/PUSH und Obsidian/weinender Obsidian/Seelenanker/verst. Tiefenschiefer tragen jetzt IMMOVEABLE
(frueher Namensliste in isPushable); ConfiguredFeature/FeatureConfiguration weg (Feature ist Record, Registry
worldgen/feature), RandomOffsetPlacement -> OffsetPlacement, PlacementModifier.modify(...,Consumer);
Loot: NumberProvider -> Holder<ContextIntProvider>, JSON "functions"/"function" -> "modifier"/"type",
LootPoolSingletonContainer -> UniformContainerBase; Villager-Trade "given_item_modifiers" -> "given_item_modifier";
TrimMaterial(paletteId) + textures/palettes/trim statt armor_trims-Atlas; ItemInHandRenderer ->
FirstPersonHandsAndItemsRenderer (Render-States, gameRenderer.firstPersonHandsAndItemsRenderer); RenderPipeline ->
com.mojang.renderpearl.api.pipeline; drop(stack,thrown,Prediction) schwingt den Arm; Entity.invulnerableTime privat,
Schadens-Cooldown ist LivingEntity.damageCooldownTime; Recipe-Datagen ueber BootstrapContext (reloadable registries).

**Fallen:** (1) Blasting/Smoking-Rezepte speichern auf 26.3 die Ofenzeit, Tempo 2.0 kommt ueber den Brennstoff und
NUR fuer Bloecke in data/minecraft/predicate/block/fast_cooking.json -> Mod-Maschinen brauchen eigenes
getSpeedMultiplier. (2) Der 26.3-Gametest-Server baut FLAT_ALL_DIMENSIONS: flaches End mit nur minecraft:the_end ->
Fabric BiomeSelectors.foundInTheEnd() trifft 1 Biom; zusaetzlich #minecraft:is_end waehlen. (3) NbtUtils.writeBlockState
schreibt "id" statt "Name". (4) BootstrapContext auf 26.3: register(k,v) + listContextElements abstrakt.
**Client-Tests 26.3:** SDL-Maustasten (links 1, mitte 2, rechts 3 - nie Zahlen, immer InputConstants.MOUSE_BUTTON_*);
gamerule/time set/weather ohne Aenderung werfen CommandSyntaxException ("already set"); ItemStack#useOn stempelt
heldItemTransformedTo in jedes Success (Identitaetsvergleich mit InteractionResult.SUCCESS scheitert);
Descriptors IMMER aus dem Vanilla-Jar (javap), nicht aus der NeoForge-gepatchten Quelle - dort hatte renderLayers
scheinbar ein int mehr. Die Welt hinter offenen Screens aendert sich auf 26.3 weiter (spaete Chunk-Sektionen): Pixelvergleiche auf das Panel
beschraenken (Ecken der Textur sind transparent -> einruecken) und "nirgends sonst" ueber den Render-State pruefen.
