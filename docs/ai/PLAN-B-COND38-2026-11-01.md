# Plan b-cond38 (IG31-38): Mod-Conduits als 3D-Inventar-Item (01.11.2026)

Ist: `strong_conduit` Item = `minecraft:special`/`conduit` (Vanilla-Schale, ungefaerbt, klein); Mighty/Evil/Mighty Evil = flache
`item/generated`-PNGs (textures/item/*_conduit.png). Platzierter Block: `StrongConduitRenderer` (Vanilla-Geometrie, Tint je
`ConduitKind.tint()`: Strong 9FE6FF, Mighty C08CFF, Evil FF6A5E, Mighty Evil C02844). Farben vom Besitzer entschieden.

Technischer Weg (kein Java): `items/<kind>.json` = `minecraft:model` mit `tints` (constant, Wert = ConduitKind.tint) auf einem Block-Modell
`models/item/<kind>.json` (parent `minecraft:block/block` fuer GUI-Winkel 30/225/0, `gui_light: side`), Elemente = Quader mit den Vanilla-
Texturen `minecraft:entity/conduit/base` (Schale 6^3, UV 32x16 wie ModelPart) bzw. `cage` (8^3) + Kern aus `open_eye`; Faces `tintindex 0`,
Kern `light_emission` (falls 26.3-Face-Feld nicht greift: ohne). `display.gui.scale` vergroessert (A ~2.0, B ~1.6; Vanilla-Groesse 1.0).
Eine Modell-Datei pro Kind, gemeinsame Texturen, keine neuen PNGs; flache PNGs entfallen (Pflicht-Texturen-Tests/layers pruefen).
Strong ebenso statt Special (damit gefaerbt wie gebaut). Alternative (verworfen): eigener SpecialModelRenderer in Java (Tint) - aufwendiger, Mixin noetig.
Varianten: A Schale (Vanilla-Conduit umgefaerbt), B Kaefig + Kern (Auge, Farbton je dust-Farbe). Vorschau: `tools/textures/cond38_preview.py`
-> /root/sb-tools-b/previews/b-cond38-preview.html (Antwortcode `COND38|form=A|size=gross|note=`).
Risiken: Face-UV bei Nicht-16x16-Texturen (Vanilla-Layout 32x16, uv in 0..16 der ganzen Textur), Kern-Leuchten, Clientsmoke noetig; Einbau erst nach Wahl.
Verifikation spaeter: Fabric-263-Client-Screenshot Beacons-Tab, data_integrity, Modul-Tests simplebeacons.
