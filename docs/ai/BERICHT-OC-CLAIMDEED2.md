# Bericht oc-claimdeed2: Claim-Urkunde Phase 2 (Editor-GUI)
Plan: `docs/ai/PLAN-CLAIM-URKUNDE-GUI-2026-10-13.md` Phase 2. Kein Claim-Tisch, keine Maps-Ebene, keine Erweiterung. Keine bestehende Textur geändert, keine neue.
- **Item:** `ClaimDeedItem` (Stapel 1, Kreativ-Tab, „Claim-Urkunde“), Rezept Papier + Tintenbeutel + Honigwabe, Kopier-Rezept `claim_deed_copy` (gebunden + leer, Kopie nicht kopierbar). Komponente `simpletweaks:deed {owner, ownerName, generation}` nur Anzeige. Leer: Rechtsklick → „Hier beanspruchen“-Blatt, danach gebunden; ohne Client-Mod wie vorher direkt.
- **Editor** (`DeedScreen`, Fabric/NeoForge/Forge): Vanilla-`MultiLineEditBox` im simplelib-Kasten (Papierfarbe, `UiBrightness`), Statuszeile „Code OK: n Personen“ / „Zeile 7: …“, rote Zeilenmarkierung + Klick springt, Zähler, Online-Chips (`Name: U` vor dem ersten Abschnitt), Hilfe-Ansicht, Kopieren/Einfügen. Fertig nur bei fehlerfreier Vorschau. Lesesicht für Fremde („Du darfst hier: …“, nie der Code).
- **Server:** `DeedService` + 4 Pakete (open/result S→C, edit/claim C→S, Codec begrenzt 4096 Zeichen/16 Fehler); jede Änderung nur über `Claims.applyCode` (Besitzer/M, Verwalter-Grenzen, Abklingzeit), Revision (Hash des Landes) gegen veraltete Editoren, 5-Tick-Drossel, Urkunde wird aus der Hand neu gelesen (Client nie vertraut, geschmiedete Komponente wirkungslos).
- **Phase-1-Berührung (bewusst):** `Claims.applyCode` löst Namen auch über Personen des Landes (lokaler Name-Cache, nie Netz), speichert UUIDs statt Namen (`ClaimCode.pin`), Editor zeigt Namen nur wenn sie zurückauflösen (`display`); leerer Code = aus Struktur erzeugt, zu groß = Lesesicht. Neu `revision/cooldownLeft/editorCode/namesFor`.
- **simplelib gebündelt** (Fabric include / NeoForge jarJar / Forge `forgeBundleSimplelib`, `>=0.2.0`), `modules.json requires`, Mod-Metadaten; Doku (`MODS-UND-FEATURES`, Prinzipien) nachgezogen. Wiki-Feature + Guide neu erzeugt (7 → 12 Seiten), Lang EN+DE.
