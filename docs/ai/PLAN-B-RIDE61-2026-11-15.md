# Plan: gleitendes Reit-Bewegungsbudget (simpleriding-3 Option B, Branch `b-ride61`, 2026-11-15)

Auftrag: Besitzer W4C=ok -> simpleriding-3 Option B (siehe `PLAN-A-W4C-2026-11-14.md` Abschnitt 6, TODO 2).
Befund dort: Gametest `simpleriding:lag_jitter` - jede gebündelte Paketfolge (2-3 Bewegungspakete in einem
Servertick) wird vom Anti-Cheat abgelehnt (11 von 59 Paketen, Rückholungen), obwohl der Reiter im Mittel
nur 95 % des Galopps fährt.

## Ist-Zustand
- `RidingSecurity.acceptMove` (`modules/simpleriding/shared/java/com/simpleriding/RidingSecurity.java`):
  pro Servertick harte Summen `distance` (3D, Deckel `safety.movementDistancePerTick`, Standard 4) und
  `horizontalDistance` (Deckel `min(cap, Hülle)`, Hülle Pferd = 0.125 + 3 x MOVEMENT_SPEED; Ghast/Nautilus
  zusätzlich 3D gegen die Hülle). Neuer Tick = Summen auf 0. Ein leerer Tick (Paket kommt verspätet) verfällt,
  das nächste Bündel überschreitet den Tick-Deckel.
- Config: `RidingConfig.Safety` + Katalog `RidingOptions.ALL` + Sprachdateien EN/DE + `balance/simpleriding/options.json`
  + `wiki/manual.json` (Kapitel je Option) + generierte Liste in `discover/RidingDiscover.java` (`tools/discover/discover.py`).
  Tests: `config_and_lang`, `all_config_bounds` (Gametests), `modules/simpleriding/tools/check_data.py` (statisch, zählt 25 Optionen).

## Neue Regel (Standard: an)
- Neue Option `safety.lenientMovementBudget` (boolean, Standard `true`). `false` = altes strenges Verhalten.
- Fenster `RidingSecurity.BUDGET_WINDOW_TICKS = 4` (200 ms). Nicht verbrauchtes Budget eines Ticks (auch ganz
  leerer Ticks) wird als Guthaben übertragen, gedeckelt auf `(4 - 1) x Tick-Deckel` = höchstens 3 Ticks Vorrat.
  Pro Tick erlaubt: `Deckel + min(Guthaben, 3 x Deckel)`; über jedes 4-Tick-Fenster also nie mehr als
  4 x Deckel + Vorrat - dauerhaft bleibt es beim Tick-Deckel (Token-Bucket).
- Jedes einzelne Paket bleibt auf einen Tick-Deckel begrenzt (kein Teleport aus angespartem Guthaben).
- Paketzahl-Grenze (`movementPacketsPerTick`) bleibt streng pro Tick (Spam-Schutz, Standard 20 reicht für Bündel).
- Ghast/Nautilus: Hüllen-Verbrauch wird in 3D gezählt (wie bisher geprüft), Pferde & Co. horizontal; damit
  bekommt ein senkrecht fliegender Ghast kein Guthaben aus ungenutzter Horizontalbewegung.
- Wechsel des Reittiers: Guthaben wird am aktuellen Deckel gekappt (kein Übertrag von schnell auf langsam über 3 Ticks hinaus).

Simulation (Python, gleiche Formeln, 40 Ticks): gleichmäßig/burst2/burst3 bei 0.225 und 0.3375 -> 0 Ablehnungen
(streng: 7 bzw. 6); 2x-Speedhack (2 Pakete je 0.95 x Deckel pro Tick) -> 38 von 80 abgelehnt, zurückgelegte
Strecke <= (Ticks + 3) x Deckel.
