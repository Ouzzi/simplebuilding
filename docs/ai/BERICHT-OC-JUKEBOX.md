# Bericht oc-jukebox (Queue Nachtrag 62: Rückport Jukebox mit Kiste darüber)
**Vanilla-Recherche (Minecraft Wiki, Stand 15.10.2026):** `minecraft.wiki/w/Java_Edition_26.4` und `/Java_Edition_26.4/Development_versions` (Snapshot 4, 13.10.2026), `/Jukebox` (Abschnitt Playlists). Vanilla: einzelne Truhe, Redstone-Truhe oder jede Kupfertruhe direkt über der Jukebox (keine Doppeltruhe); neue Tags `#jukebox_containers` (Block + Item). Leere Jukebox nimmt die Platte aus dem ersten Slot mit Platte (leere Slots/Nicht-Platten übersprungen, Slot-Reihenfolge, Wrap); Platte zu Ende = Tausch mit der nächsten; keine weitere Platte in der Kiste = die eingelegte Platte wird wiederholt; Auswerfen springt zur nächsten; Tooltip „Playing Next“. NICHT dokumentiert (Wiki-Lücke): Redstone-/Trichter-Details, Cursor-Speicherung, Tag-Inhalt. Unsere Annahmen dazu unten.
**Umgesetzt (26.3, Fabric/NeoForge/Forge):** `util/JukeboxPlaylist.java`, Mixins `JukeboxBlockEntityPlaylistMixin` (Tick-Ende + Cursor in den Block-Entity-Daten, Key `simplebuilding_playlist_slot`) und `JukeboxBlockPlaylistTickerMixin` (Vanilla tickt eine leere Jukebox nicht; mit Flag tickt sie, leere pollt alle 10 Ticks, fertige Platte wird im selben Tick getauscht, damit ein Trichter darunter sie nicht stiehlt). Quelle 26.2: leere Mixin-Stubs. Flag `McVersion.JUKEBOX_CHEST_PLAYLIST` (26.3 true, 26.2 false) plus Laufzeit-Sperre: nicht-leerer Vanilla-Tag `#minecraft:jukebox_containers` schaltet die Mod-Umsetzung ab. Tabelle in `docs/ai/PRINZIPIEN-VANILLA-RUECKPORTS.md` gefüllt; Wiki (`music_discs`, EN+DE), `docs/MODS-UND-FEATURES.md` nachgezogen.
**Entscheidungen/Abweichungen:** (1) Ohne weitere Platte in der Kiste wird die fertige Platte wiederholt (Vanilla), nicht „zurück in die Kiste“ wie im Queue-Text (sichtbar gleich, wenn die Kiste sonst keine Platte hat). (2) Container per Code (`ChestBlock` SINGLE, `ChestBlockEntity`; deckt Kupfer-, Redstone- und die Mod-Truhen-Stufen ab) statt per eigenem Tag; Truhen mit ungeöffneter Beute werden ignoriert; `WorldPermissions.mayAutomate` wird beachtet. (3) Cursor (Slot der zuletzt genommenen Platte) speichern wir, sonst springt die Reihenfolge nach Tauschen zurück. (4) Kein „Playing Next“-Tooltip, keine Config-Option (Tooltip-Regel; nur Flag). (5) Jukebox-Verstärker: unverändert; Tausch = neues Start-Event, Funk-Kette trägt die neue Platte (Test). Eigene Schallplatten (Voidline usw.) sind normale `jukebox_playable`-Items und laufen mit.
**Tests:** `python3.12 tools/testrunner/run.py --targets fabric-263,neoforge-263 --filter 'simplebuilding:jukebox_playlist*'` -> „alles gruen: 20/20 bestanden, 0 rot“ (10 Tests je Loader: einlegen, tauschen über echten Tick, Reihenfolge/Wrap mit Mod-Platte, Wiederholen bei leerer/Nicht-Platten-Kiste, nichts bei leerer/fehlender/Doppelkiste, volle Kiste, Auswerfen, Cursor-Speicherung, Flag/Tag, Verstärker). Gegenprobe: ein erster Lauf war rot (Test rechnete `hasFinished` falsch, +20 Ticks) und wurde im Test korrigiert. Regression: `--filter 'simplebuilding:music_disc*'` -> „alles gruen: 32/32“.
