# Plan b-aud6 (24.10.2026): AUD-6 Bild-Bauplan Stufe 3 - Bild als Karte / Kartenwand

Grundlage: `docs/ai/KONZEPT-BILD-BAUPLAN-2026-10-19.md` (Stufe 3), Stufen 1+2 (b-picture) vorhanden: `simplelib.api.image.{PixelPalette,PixelArt}`.
NUR 26.3 Fabric (Besitzer 22.10.): Neo-/Forge-Einhaenge und Client-Befehl dort offen (Memory).

## Entscheidungen
1. Ergebnis = **Vanilla-Karten** (`filled_map`, gesperrt, Massstab 0) je 128x128-Kachel: Kartenwand ueber Vanilla-Rahmen, Karten sind auch ohne Simple Maps lesbar.
2. Bild kommt wie bei der Blaupause als PNG aus `config/simplemaps/images/` (eigener Ordner: Simple Maps bleibt allein spielbar, kein SB-Import). Umrechnung nur im Client: `PixelArt.fit/scale/quantize` mit Palette aus den Spiel-`MapColor`s (61 Grundfarben x 4 Helligkeiten, Id 0 = frei).
3. Seitenverhaeltnis bleibt: Kantenlaenge N Karten (1..`pictureMapMaxSide`), Spalten/Zeilen aus dem Verhaeltnis, Bild mittig, Rand = frei (Karten-Id 0).
4. Eigene Nutzlast `PictureMapPayload(cols, rows, col, row, byte[16384])` Client->Server, je Kachel eine (Vanilla-Grenze 32 KiB). Server prueft: Schalter, Rechtestufe, Groesse, Index, Laenge 16384, jedes Byte eine gueltige Kartenfarbe, Rate (max 2*N^2 Kacheln je Minute und Spieler). Karte landet im Inventar (voll: Boden), Name "Bild x/y".
5. Config (`simplemaps-server.json`): `pictureMap` (Standard **an** seit WB24-7, Besitzer 24.10.), `pictureMapMaxSide` 1..4 (3), `pictureMapPermission` 0..4 (0).
6. Einstieg: Fabric-Client-Befehl `/simplemaps picture` oeffnet `PictureMapScreen` (Datei, Groesse, Dithering, Vorschau, "Karten erzeugen"). Antworten des Servers als Chat-Nachricht (kein Zusatz-S2C-Paket).
