## Teil 1: Raster-Editor E2/E3 (UI erst exemplarisch)
- E2 = Raster (Piano-Roll) schreibt Code; E3 = Raster als zweiter Reiter, Code bleibt Wahrheit.
- Nur Vorschau, kein Java: `/root/sb-tools-b/previews/aud7-music-editor.html` (E2 A/B, E3 A/B, bedienbar, WebAudio, Kontrast >= 4,5:1,
  Jukebox-Braun wie BurnScreen). Java erst nach Besitzer-Wahl; NoteCode bleibt einzige Wahrheit (Raster liest/schreibt Notencode).

## Teil 2: Client-Schalter „Fremde Musik laden“
- Neu `MusicClientConfig` (`config/simplemusic-client.json`, Schluessel `loadForeignMusic`).
- Entscheidung: Standard AN (= heutiges Verhalten). Der Server liefert ohnehin nur freigegebene bzw. eigene ausstehende Tracks
  (`TrackStore.Track#audibleFor`), die Konzept-Stufe „nur von Freigegebenen“ ist damit serverseitig erzwungen; ein Standard AUS
  wuerde jede Server-Musik still abschalten. Zwei Zustaende statt drei (Client kennt den Status eines Hashes nicht).
- AUS: kein Download, kein Abspielen fremder Tracks (TrackPlayer, PocketPlayer), eigene Uploads dieser Sitzung (Hash vor dem Senden
  gemerkt) sind erlaubt; Hinweis einmal je Track in der Aktionsleiste (`simplemusic.foreign_off`). Vanilla-Songs unberuehrt.
- MusicServer (Upload-Worker, b-revupload24) und SheetPlayback nicht angefasst.
- Tests: JUnit `MusicClientConfigTest`; Client-Logik headless nicht testbar (nie Client).
- Lang de/en, Wiki-Eintrag (config_server), check_data prueft den Schluessel.
