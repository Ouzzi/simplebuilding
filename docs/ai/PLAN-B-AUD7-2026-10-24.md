## Teil 1: Raster-Editor E2/E3 (UI erst exemplarisch)
- E2 = Raster (Piano-Roll) schreibt Code; E3 = Raster als zweiter Reiter, Code bleibt Wahrheit.
- Nur Vorschau, kein Java: `/root/sb-tools-b/previews/aud7-music-editor.html` (E2 A/B, E3 A/B, bedienbar, WebAudio, Kontrast >= 4,5:1,
  Jukebox-Braun wie BurnScreen). Java erst nach Besitzer-Wahl; NoteCode bleibt einzige Wahrheit (Raster liest/schreibt Notencode).

## Teil 2: Client-Schalter „Fremde Musik laden“
- Neu `MusicClientConfig` (`config/simplemusic-client.json`, Schluessel `loadForeignMusic`).
- Entscheidung: Standard AN (= heutiges Verhalten). Der Server liefert ohnehin nur freigegebene bzw. eigene ausstehende Tracks
  (`TrackStore.Track#audibleFor`), die Konzept-Stufe „nur von Freigegebenen“ ist damit serverseitig erzwungen; ein Standard AUS
  wuerde jede Server-Musik still abschalten. Zwei Zustaende statt drei (Client kennt den Status eines Hashes nicht).
- AUS: kein Download, kein Abspielen fremder Tracks (TrackPlayer, PocketPlayer), eigene Uploads dieser Sitzung (Hash vor dem Senden
  gemerkt) sind erlaubt; Hinweis einmal je Track in der Aktionsleiste (`simplemusic.foreign_off`). Vanilla-Songs unberuehrt.
- MusicServer (Upload-Worker, b-revupload24) und SheetPlayback nicht angefasst.
- Tests: JUnit `MusicClientConfigTest`; Client-Logik headless nicht testbar (nie Client).
- Lang de/en, Wiki-Eintrag (config_server), check_data prueft den Schluessel.

## Teil 3 (b-wb24editor, WB24-4): Raster-Editor in Java (Besitzer-Wahl E2 A + E3 B)
- Reine Logik `com.simplemusic.sheet.NoteGrid` (kein Spielcode): `fromCode(code, policy)` nutzt `NoteCode.parse` (nur bei
  fehlerfreiem Code ein Raster, sonst null = Raster bleibt stehen), `of(Song)`, `toCode()` schreibt flachen Notencode
  (`tempo`, eine Spur je Instrument, Akkorde `[..]`, `@vol` wenn != 1, Klang-Instrumente als `$sN = sound id`, mehr als 4
  Töne je Schritt eines Instruments als zusätzliche Stimme `$name_2 = name`), `toggle` (Note setzen/weg, verweigert über
  MAX_CHORD/MAX_TONES_PER_STEP/MAX_TRACKS), `remove` (Rechtsklick). Notencode bleibt die Wahrheit: Raster liest nur Song.
- `SheetMusicScreen`: bei Notenblättern ohne Upload geteilt (E3 B) — Raster links (25 Töne je Instrument, Schritte mit
  Mausrad blättern, Taktstrich alle 4), Code rechts (UiCodeArea), live in beide Richtungen; Instrument-Wahl per Knopf
  (Durchschalten, E2 A), Linksklick = Note an/aus, Rechtsklick = löschen; Kopieren-Knopf bleibt. Signiert = Raster nur
  Anzeige. Fehler im Code: Raster bleibt, Fehler unten wie bisher. Rasterklick schreibt den Code flach neu (Hinweis).
- Farben im Braun der BurnScreen; Text über UiContrast.ensure (>= 4,5:1), Notenfarbe auf Zelle >= 3:1.
- Lang de/en: `simplemusic.editor.instrument`, `simplemusic.editor.grid.hint`, `simplemusic.instrument.<name>`.
- Tests: JUnit `NoteGridTest` (Rundweg Code->Raster->Code gleicher Song, Toggle, Grenzen, Fehlerfall, Stimmen, Klang) +
  Gametest `simplemusic:note_grid_round_trip` in MusicTests (Modul + standalone). Screen nur kompiliert (kein Client-Lauf).
