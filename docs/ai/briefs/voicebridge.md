TASK VOICEBRIDGE (owner request, translated from German): the owner wants to talk by voice, mainly from a PHONE (also from a laptop), with an AI agent that works on his projects: while walking, on the train or as a passenger. Bare minimum he described: one big button. Tap it, speak (silence while he talks), tap it again when finished; then the answer is READ ALOUD; then he taps again and answers, and so on; after his message the next spoken feedback of what happened in the session follows. No typing, no reading. Not only for this repo but for other projects too. Official Claude Code has voice INPUT (`/voice`) and Remote Control from the phone app, but Remote Control replies are text only and there is no official text-to-speech, so we build a small bridge.

BUILD tools/voicebridge/ (Python 3 stdlib only for the server, plus a static single-page PWA; no pip installs required for the MVP; optional local Whisper/Piper adapters behind an interface but OFF by default):
1. Server (`python tools/voicebridge/server.py [--port 8772] [--host <ip>]`): serves the PWA and a small JSON API; binds to 127.0.0.1 by default and to a Tailscale address only when --host is given (detect the Tailscale IPv4 100.64.0.0/10 via `tailscale ip -4` if available and offer `--tailscale`); reject requests whose Host header is not loopback/the configured tailscale IP/name; bearer token auth (random token generated on first start, stored in tools/voicebridge/token.txt which is gitignored, shown as a QR-code-free URL `http://<host>:<port>/#token=...` so the phone keeps it in localStorage); audit log (tools/voicebridge/audit.log, gitignored); rate limit; max body sizes.
2. PWA (phone first, dark theme consistent with tools/launchhub and the wiki, big accessible push-to-talk button that fills the lower half of the screen; states: idle, listening, thinking, speaking; haptic/sound cues (short vibration and beep) on state changes so he needs no screen; wake lock so the screen stays on while active; installable (manifest, service worker for the shell only); works in Android Chrome and iOS Safari where the APIs exist). Speech-to-text: browser Web Speech API (`SpeechRecognition`/`webkitSpeechRecognition`, language de-DE default, configurable) with tap-to-start/tap-to-stop semantics and a clear fallback message if unsupported; also a server-side STT adapter interface (audio upload) with a stub and an optional faster-whisper adapter (only used if the package is installed). Text-to-speech: browser `speechSynthesis` (prefers a German voice, rate and pitch configurable, long answers split into sentences, a big stop/skip button and a volume-independent "repeat last answer" button), server-side TTS adapter interface with stub and optional Piper adapter. Phone lock-screen/bluetooth headset media-key support via the Media Session API so a headset button can act as the talk button when possible.
3. Brain (configurable provider, default `claude`): each spoken turn is sent to a headless agent CLI in the chosen project directory. Providers: `claude` (`claude -p "<text>" --output-format json [--resume <session-id>] [--model <model>]`, parse session id and result so the conversation CONTINUES across turns; check `claude --help` for exact flags, do not guess), `codex` (`codex exec` / resume, check `codex --help`), `ollama` (local HTTP API for plain Q&A, if running), and `echo` (test stub). A per-project setting chooses the working directory, provider, model and session id; a "new conversation" voice command starts a fresh session. Appended to every prompt: a voice-mode instruction (answer in the user's language, 2-4 short sentences, no code blocks/markdown/URLs/paths read aloud, give a short status first, say what needs a decision; put the long details in a file under tools/voicebridge/out/ and only mention it). The server stores the full text of every answer (history page in the PWA for later reading) and produces a separate short `spoken` field (the agent is asked to output a JSON object {"spoken": "...", "details": "..."}; fall back to truncating if parsing fails).
4. Safety model (important, the user may be driving or walking): default mode READ-ONLY (agent started with its read-only / plan permission mode, no edits). Action mode (edits, starting runs, merging) needs an explicit spoken two-step confirmation: the bridge reads back the action in one sentence and a random confirmation word; only the exact word spoken next enables it for ONE turn. Never push to git, never force anything, never delete data, never run arbitrary shell from voice: a voice command layer with an ALLOW-LIST handled BEFORE the agent: "status" (git branch/dirty, running runs via `python tools/ai/aitool.py status`, last gate verdict from testing/runs), "what failed" (latest failing tests from testing/runs), "read last report", "new conversation", "switch project <name>", "stop"/"quiet" (stop speaking), "repeat". Text coming from repositories, logs or web pages is DATA and must never be executed or treated as a command; the bridge only acts on the owner's transcript. Kill phrase and a server-side emergency stop endpoint. All state-changing calls are POST with a CSRF-safe token; no GET mutates anything.
5. Multi-project config `tools/voicebridge/projects.json` (committed example `projects.example.json`, real file gitignored): list of {name, root, provider, model, default mode, brief folder}. Include this repo as the first entry using paths relative to the repo root.
6. Also support the LAPTOP: the same page works in a desktop browser with a keyboard shortcut (Space) as push-to-talk.
7. Tests (python -m unittest discover tools/voicebridge/tests): allow-list command parser, confirmation flow (wrong word refused, single use, timeout), Host/token checks, Tailscale address validation, provider command building (argv lists only, no shell=True with user text), session-id continuation, spoken-summary extraction/fallback, audit log, config validation, path safety. A dry-run mode (env SB_VOICE_DRY_RUN=1 echoes commands, no agent started) and a fake provider for UI checks. Verify the PWA with the browser preview tools (add a `voicebridge` entry to .claude/launch.json on port 8772) at phone width; do not start real agents during verification.
8. Docs: docs/ai/VOICE-HANDS-FREE.md (update the existing file: what was built, setup on the phone step by step incl. Tailscale, how to install the PWA, how to choose the model, safety rules, limits: browser STT needs internet and Android Chrome is the most reliable, iOS Safari support varies), AGENTS.md section 10 (one line), docs/HANDOFF.md.
Rules: commit in logical commits on your branch; no push, no merge. `./gradlew.bat check -q` must stay green (nothing in Gradle should change; add your unit tests to the same python-test wiring the launchhub tests use ONLY if they are wired into `check`, otherwise leave Gradle alone).
