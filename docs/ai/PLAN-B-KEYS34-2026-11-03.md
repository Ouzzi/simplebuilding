# Plan b-keys34: Tastatur-Layouts und Editor (Simple Keybinds), 03.11.2026

Besitzer (Punkt 4): nicht nur US; DE (ISO-QWERTZ), UK (ISO), FR (AZERTY) als Vorgaben; Editor fuer eigene Layouts; kein Ueberlappen, keine doppelte Taste; jede im Editor gedrueckte, fehlende Taste erscheint automatisch.

## Ist-Stand
- `KeyboardLayout` (simplelib, reine Daten): Cell(code=GLFW-Zahl, label, x,y,w,h in Viertel-Tasten); `german` tauscht nur Y/Z. Identitaet einer Taste = `keyName(code)` (`key.keyboard.*`), unabhaengig von 26.3-SDL-Nummern -> ein Layout beschreibt Position + Beschriftung, der Code bleibt die physische Taste.
- `KeysScreen` (simpleinterfaces): Tastatur-Ansicht mit 60/75/100 % und QWERTZ-Knopf.

## Entscheidungen
1. Cell bekommt optional ein zweites Rechteck (L-foermige ISO-Enter). Hit-Test, Zeichnen, Ueberlapp-Pruefung kennen beide Rechtecke.
2. Vorgaben `us|de|uk|fr` erzeugt `KeyboardLayout.cells(size, id)`; ISO: Enter L (6 breit oben, 5 unten), Extra-Taste `#` links neben Enter (BACKSLASH), `<`/`\` links neben Y/Z (WORLD_1 = 161), Beschriftungen je Layout (Y/Z, AZERTY, Umlaute). Groesse 60/75/100 % bleibt bei Vorgaben.
3. Eigene Layouts sind feste Tastenlisten (Groesse-Knoepfe dann aus). Speicherort: `config/simpleinterfaces-keyboards.json` (Client-Datei; gewaehltes Layout + eigene Layouts, Tasten per Minecraft-Name, damit Versionswechsel der Nummern nichts kaputt macht). Nicht in `simpleinterfaces.json`, damit keine Config-Screen-Regeln noetig sind.
4. Editor (`KeysEditorScreen`): Start = Kopie des gewaehlten Layouts. Taste anklicken = waehlen; Ziehen oder Pfeil-Knoepfe = verschieben (Viertel-Tasten, Shift = ganze Taste); B+/B-/H+/H- = Groesse; L-Knopf = Form (Rechteck/L); Beschriftung-Feld; Entfernen; "Taste hinzufuegen" (naechste Taste inkl. Esc). Jede andere physische Taste, die im Editor gedrueckt wird: im Layout vorhanden -> wird gewaehlt, fehlt sie -> automatisch neue Taste auf dem ersten freien Platz unter dem Bild (Beschriftung vom US-Standard, editierbar). Nicht darstellbare Tasten (ohne bekannten MC-Namen) -> Hinweis.
5. Validierung rein in `KeyboardEdit` (testbar): Aenderungen, die ueberlappen/aus dem Raster (160 x 60) laufen, werden abgelehnt (Hinweis rot), doppelte Taste unmoeglich (Code ist Schluessel), Speichern nur mit gueltigem Namen (1-16 Zeichen, nicht us/de/uk/fr) und gueltiger Liste.
6. Luecken ausgearbeitet: Layout-Wechsel per Knopf (zyklisch, Tooltip mit vollem Namen); Eigenes Layout loeschen im Editor; Kopie eines eigenen Layouts erlaubt; FR/DE-Zahlenreihe zeigt Basis-Beschriftung (ohne Shift/AltGr-Ebenen - bewusst, uebersichtlich).
