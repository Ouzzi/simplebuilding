# PLAN b-net37 (01.11.2026): IG31-37 Fässer und Shulker-Kisten im Kisten-Netzwerk

Ist-Stand: `ChestNetwork.Storage` arbeitet schon über `BlockEntity instanceof Container` (Zählen, Entnehmen, Einlagern, Sperre via `BaseContainerBlockEntity.canOpen`). Nur die Anschluss-Prüfungen waren auf `ChestBlock` festgenagelt: `InterfaceBlock` (Platzieren, canSurvive, updateShape), `ChestNetwork.scan`, `ControllerLevel.rankOf`.

Änderung (kleinste): `ControllerLevel.mountable(Block)` = Chest/Barrel/ShulkerBox (Vanilla- und Tiered-Klassen, Tiered erben ChestBlock bzw. ShulkerBoxBlock); `rankOf` liefert dafür 0 (Vanilla) bzw. Tier+1 (Reinforced..Enderite-Shulker); Interface und Scan nutzen `mountable`. Kein Sonderfall je Block, Zugriff weiter über die Container-Schnittstelle.
Shulker in Shulker: `Storage.insert` prüft für Shulker-Ziele `TieredShulkerBoxBlockEntity.canHold` (Vanillas Regel, auch für Vanilla-Kisten, deren `canPlaceItem` offen ist). Inhalt bleibt in der Kiste: nichts wird ausgelagert, Abbauen behält Inhalt wie bisher.
Test: `network_barrels_and_shulker_boxes_join` (Katalog StorageTests.ALL + @GameTest ModuleGameTest): Interface an Fass/Shulker, Terminal zählt, Entnehmen, Einlagern, Shulker-in-Shulker abgelehnt, Ränge.
Risiko: Fass/Shulker in bestehenden Welten werden nur mit Interface Teil des Netzes (opt-in), keine Migration. Offen: Tooltip/Guide-Text „Truhen“ unverändert.
