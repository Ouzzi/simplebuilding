# Plan b-maps20 (19.10.): Simple Maps – Chunk-Filter, fremde Dimensionen, Shop-Symbol

Queue: `.claude/QUEUE.md`, Block „Besitzer 19.10. abends – Nachtrag“, drei b-maps20-Zeilen. Basis claude-wave1 dbd2acf0d.

## Ist-Zustand
- `net/LayerService.handle`: Ebene „Geladene Chunks“ setzt das Bit für jeden erkundeten Chunk mit
  `getChunkNow != null` – auch Chunks, die nur ein anderer (z. B. unsichtbarer) Spieler lädt. Positionsleck.
- Fremde Dimension: `MapsClient.jammed` → Karte in der Hand zeigt **nur** Rauschen (`StaticTexture`, kräftig,
  ganze Fläche). Der Bildschirm (`WayfinderScreen`) zeichnet die Kacheln schon, Server liefert Kacheln
  dimensionsunabhängig (`MapsNetwork.handleTiles`).
- Shops: Simple Shops registriert die Quelle `shops` (Marker-Art `shop`) über `framework.api.MapLayerSources`;
  der Client zeichnet jede Quelle als farbige Raute. Webkarte (`web/WebExport.markers`) kennt nur Spieler.

## Umsetzung
1. **Chunk-Filter (Server, `LayerService`)**: Bit nur, wenn erkundet + geladen **und** (a) von einem Chunkloader/
   `/forceload` erzwungen (`level.getForceLoadedChunks()`, Vanilla-Schnittstelle, Chunkloader von SB nutzen
   `setChunkForced`) oder (b) im eigenen Ladebereich des Betrachters: gleiche Dimension und Chebyshev-Abstand
   ≤ Server-Sichtweite (`ChunkTrackingView.isInViewDistance`). Chunks anderer Spieler erscheinen nie.
   Hilfsmethode `LayerService.shownChunk(...)` öffentlich für den Test.
2. **Fremde Dimension (Client + reine Logik)**:
   - `ViewTexture.compose(..., jam, tick)`: erkundete Pixel normal, nur unerkundete (Farbe 0) bekommen ein
     dezentes, getöntes Rauschen (halbtransparent, schwache Amplitude, kein Riss); bei `jam` jeder Tick neu.
   - `MapsClient.fillHandState`: statt `StaticTexture` die Karte; Mitte = Spielerposition umgerechnet
     (Oberwelt↔Nether 8:1, `WayfinderMapItem.coordScale`), kein Spielerpfeil, kein Todeskreuz.
   - Server: unverändert (Kacheln werden dimensionsunabhängig geliefert) – per Gametest belegt.
   - `StaticTexture` bleibt nur für die Tönung (`tint`); die Klasse wird entfernt, wenn ungenutzt.
3. **Shop-Symbol**:
   - `MapsIcons` (shared): `SHOP_KIND = "shop"`, `MONEY_BILL = simplemoney:money_bill`; `shopIcon()` = Item nur,
     wenn `SimpleMaps.modLoaded("simplemoney")` und das Item registriert ist (Regel 4: isModLoaded, keine Klasse).
   - Client `MapLayers.draw`: Marker-Art `shop` + Symbol vorhanden → Geldschein (Item, 10 px) statt Raute.
   - Webkarte: `markers.json` bekommt `shops` (Dimension, x, z, Zeilen, `icon` = `money_bill`|`diamond`) – nur
     mit neuem Schalter `webShops` (Standard **aus**, Datenschutz wie Spieler/Claims), nur auf erkundeten
     Kacheln, mit `webHideClaims` nicht in geschützten Chunks. Ist Simple Money da, wird `money_bill.png`
     (Klassenpfad, wenn lesbar) als `icons/money_bill.png` mitexportiert; die Ansicht zeichnet sonst einen
     gezeichneten Geldschein bzw. eine Raute.
   - Metadaten: `simplemoney` optional (modules.json `optional`, Fabric `suggests`, NeoForge/Forge optional).
4. Doku: `docs/SIMPLEMAPS-WEBKARTE.md` (webShops), Modul-Wiki falls nötig, Queue-Zeilen [x].

## Tests (Gametests in `test/MapsTests` bzw. `WebTests`, Fabric-Adapter `ModuleGameTest`)
- `layers_own_chunks`: ferner, geladener, erkundeter Chunk mit zweitem Spieler daneben → kein Bit; erzwungen →
  Bit; eigener Chunk → Bit; Betrachter in anderer Dimension → nur erzwungene.
- `other_dimension_tiles`: Nether-gebundene Karte, Spieler in der Oberwelt → Kacheln mit Farben kommen an;
  `coordScale` (Oberwelt↔Nether 8, End 1).
- `shop_icon`: ohne simplemoney leer, mit (modLoaded umgebogen) und registriertem Item gesetzt bzw. leer.
- `web_shops`: Standard aus → keine shops; an → Shop auf erkundeter Kachel drin, unerkundet nicht,
  `webHideClaims` + Schutz → raus; `icon` folgt `modLoaded`.
- Ziele: module-simplemaps-fabric-263, -neoforge-263, -standalone-fabric-263; Compile aller Loader; `check`.

## Risiken / offen
- Client-Darstellung (Rauschen, Geldschein, Mitte) offline nicht prüfbar → Client-Abnahme offen.
- Sichtweite: Server-Sichtweite statt individueller Client-Sichtweite (Obergrenze, deterministisch) –
  zeigt höchstens Chunks im eigenen Umkreis, nie fremde Positionen.
