# Plan: Simple Optimization Stufe 1 + erste Teile (`claude-opt1`, 18.10.2026)

Grundlage: `docs/ai/KONZEPT-SIMPLE-OPTIMIZATION-2026-10-17.md` (§4 Kompat, §5 Config, §6 Benchmark, §7 Stufen,
§9 Besitzer-Antworten: alle Empfehlungen übernommen, Benchmarks auf sb-test). Queue: (e1)+(e2), Zeile „claude-opt1“.
Lizenzregel §1: kein fremder Code; Technik nur aus Projektbeschreibungen + eigener Analyse des Vanilla-Codes
(Vineflower-Dekompilat des 26.3-Jars, nur lokal, nie eingecheckt).

## Ist-Zustand
- Super-Mod-Muster: `simpleaesthetics` (kein Inhalt, `Config` mit `enableSimpleX`, framework `SubMods`, Gametests
  `sub_mod_switch`/`config_file`, Money-Datei „nothing to trade“, kein Guide, kein Discover-Eintrag).
- Gerüst-Werkzeug `tools/newmod.py`; Manifest `modules/modules.json` erlaubt Fabric-only (`loaders: ["fabric"]`).
- framework (`:framework`, reines Java, JUnit) wird in jedes Modul genestet → Ort für die loader-freie Kompat-Logik.
- Vanilla 26.3 Ansatzpunkte (eigene Analyse):
  - O1: `ModelBlockRenderer#shouldRenderFace(BlockAndTintGetter, BlockState, Direction, BlockPos)` (privat, Level + Nachbar-Pos
    vorhanden); Vanilla cullt Blatt↔Blatt nur bei „cutoutLeaves=false“ (`LeavesBlock#skipRendering`).
  - O7: `Lightmap#render(LightmapRenderState)` lädt bei jedem Tick-Update (Flackern ändert `blockFactor` immer) neu hoch.
  - M1: `ServerNameResolver#resolveAddress` → `ServerAddressResolver.SYSTEM` (`InetAddress.getByName`) und danach
    `AddressCheck#isAllowed(ResolvedServerAddress)` → `getHostName()` = Rückwärts-DNS bei IP-Literal; dazu SRV-Abfrage.
  - M2: `ClientTelemetryManager#createEventSender` (privat) liefert sonst einen echten Sender.
  - S5a: `PlayerList#setViewDistance/setSimulationDistance`, `MinecraftServer#getAverageTickTimeNanos`.

## Umsetzung
1. **Module** (Fabric 26.3, `loaders:["fabric"]`; NeoForge/Forge übersprungen laut Konzept §5.2/§8.2):
   `simpleoptimization` (Super-Mod, nur Schalter `enableSimpleOptRender/Memory/Server`, nestet die 3 Sub-Mods),
   `simpleoptrender` (Client: O1 `leaf_culling`, O7 `lightmap_cache`, M1 `fast_ip_ping`, M2 `no_telemetry`),
   `simpleoptmemory` (C+S, noch ohne Bereich – O4/O5 ab Stufe 4; nur Schalter, Config, Erkennung ferritecore/modernfix im Log),
   `simpleoptserver` (Server: S5a `dynamic_distance`, Befehl `/simpleopt status`).
   Je Modul: `config/<id>.json`, Lang EN/DE, `wiki/manual.json`, Money-Datei (leer), `tools/check_data.py`,
   Modul-Gametests + Standalone-Target. Kein Guide-Buch/Discover (keine Items, wie `simpleaesthetics`).
2. **Kompat-Engine** in framework `OptCompat` (seit 0.1.12, loader-frei): `Area` (id, Seite, Fremd-Mod-IDs, `coexists`),
   `Mode` auto|ours|theirs|off, `resolve(...)` → `Decision` (aktiv, Grund, Fremd-Mod, Hinweis), `table(...)` für die Logzeile.
   Regeln (§4.3): off → aus; Sub-Mod-Schalter aus → aus; kein Fremd-Mod → an; theirs → aus; ours → an nur bei `coexists`,
   sonst Warnung + Rückfall theirs; auto → Prioritätstabelle (`ours` wie ours, sonst theirs).
   Mod-IDs aus den fabric.mod.json der 26.3-Jars (Modrinth, 18.10.): `cullleaves`, `moreculling`, `badoptimizations`,
   `servercore`, `fastipping`, `no-telemetry`, `ferritecore`, `modernfix`, `sodium`, `lithium`, `immediatelyfast`,
   `entityculling`, `c2me`, `scalablelux`, `vmp`, `bobby`, `iris`; ohne 26.3: `noisium`, `voxy`.
   Prioritätstabelle je Sub-Mod `data/<submod>/priorities.json` (Start überall `theirs`; Abweichung zu §5.1: je Sub-Mod
   statt einer Datei im Super-Mod, weil jedes Sub-Mod allein laufen muss).
   Mixin-Plugin je Sub-Mod (`IMixinConfigPlugin`): entscheidet in `onLoad` (liest Config + Super-Mod-Schalter direkt aus
   den Dateien, da vor `onInitialize`), `shouldApplyMixin` nach Unterpaket `mixin.<area>`; Logzeile mit Entscheidungstabelle.
3. **Teile**
   - O1: eigene Regel `LeafCulling.cull(level, state, neighborPos, dir, depth)`: Fläche Blatt→Nachbar wird weggelassen, wenn
     der Nachbar und die `depth` Blöcke dahinter Blätter (`#minecraft:leaves`) sind. Luft-/Nicht-Blatt-Nachbar → Fläche bleibt.
   - O7: Upload überspringen, wenn alle Uniform-Werte weniger als eine halbe 8-Bit-Stufe (0,5/255) vom zuletzt
     hochgeladenen Stand abweichen (je Lightmap-Instanz; erster Upload immer).
   - M1: IP-Literal (Guava `InetAddresses`, ohne DNS) → `InetAddress.getByAddress(literal, bytes)` (Hostname = Literal, kein
     Rückwärts-DNS) und keine SRV-Abfrage.
   - M2: `createEventSender` → `TelemetryEventSender.DISABLED`.
   - S5a: nur dedizierter Server; alle `stepSeconds` MSPT-Mittel prüfen: > `targetMspt` → Sichtweite −1 (bis `minView`),
     < 0,8·target → +1 (bis server.properties). Simulationsweite nur mit `adjustSimulation: true` (Standard **aus**, weil
     sie Farmen/Wachstum ändert = spielverändernd, Konzept §5/§9.4). Grenzen: nie über server.properties, nie unter 3.
4. **Benchmark** `tools/bench/`: `modsets.json` (Modrinth-Version-ID + SHA-512, nur 26.3), `fetch_mods.py`,
   `run_bench.py` (Szenarien a–d je Bereich, N Läufe, frische JVM je Lauf), Mess-Entry `BenchClientTest`
   (Client-Gametest, `-PmoduleClientTest=bench`, eigener Mods-Ordner `-PbenchModsDir`): feste Szene (Seed, Mittag,
   Wetter/Spawns aus, Blätter-Kuben für K1), Kameraweg (Kreis), Warmup, Messung; Kennzahlen Frame-Zeit Mittel/1%-Low/p99,
   MSPT, Heap nach GC, Startzeit, Chunk-/Mesh-Ladezeit; `results.json` + `report.html`. Einmal fahren: O1 (vs Cull Leaves,
   More Culling) und S5a (vs ServerCore). GPU-gebundene Werte (Frame-Zeit unter llvmpipe) = „nur Tendenz“.

## Risiken
- Mixin-Plugin-Zeitpunkt: Config muss ohne MC-Klassen lesbar sein (nur Gson + Dateien). Fehlschlag → Bereich aus + Log.
- Client-Gametest unter llvmpipe langsam → Frames statt Sekunden zählen, N=3.
- Fremd-Mod-Jars im Dev-Lauf (26.x unobfuskiert): Lauf scheitert → Szenario als „nicht lauffähig“ im Bericht.
- framework-Version 0.1.12: parallele Branches können ebenfalls hochzählen → beim Merge zusammenführen.
