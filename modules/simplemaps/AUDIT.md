# Audit simplemaps (a-audsb31e1, 12.11.2026)

Basis `hub/b-bundle188` 9dfb3f643, nur MC 26.3 Fabric (Forge/NeoForge nicht Teil des Releases). Umfang des Mods: 66 Java-Dateien /
8,4k Zeilen (shared + fabric, ohne Tests/Forge/NeoForge), Tests 2,6k Zeilen. Geprueft wurde **risikogeleitet** (P1-Klassen zuerst:
alle C2S-Payloads, Kartentisch/Amboss, Rahmen, Bildkarten, HTTP-Server); der Karten-Bildschirm (1,3k Zeilen Client) nur am Klick-/Menuepfad.
Zusatzeingabe BEW39 (`/root/sb-tools-a/bewertung39/simplemaps.json`) ist unten eingeordnet.

## Besitzer-Fragen (AUDSB31E1)
- **Q1 Bildkarten ohne Kosten (P2-4).** Kontext: `/simplemaps picture` (Standard an, jeder darf, Besitzer 24.10.) erzeugt Karten ohne Material;
  ein Skript-Client kann dauerhaft ~1000 Karten/Stunde in die Welt schreiben. Optionen: **A** so lassen (nur Rate). **B** neue Configs: `pictureMapPermission` 2
  (nur Spielleiter). **C** jede Bildkarte verbraucht eine leere Karte (`minecraft:map`) aus dem Inventar (Kreativ frei), wie Vanillas Kopieren.
  Empfehlung **C**: Missbrauch wird teuer, bleibt fuer normale Spieler nutzbar, passt zu Vanilla (A12); B nur, wenn Server das nicht wollen.
- **Q2 Karten im Speicher (P2-3).** Kontext: jede benutzte Karte bleibt bis zum Neustart geladen (32 KiB je Kachel, Standard 4096 Kacheln = 128 MiB, Obergrenze 16384 = 512 MiB);
  Web-Export laedt zusaetzlich alle Karten. Optionen: **A** lassen, nur dokumentieren. **B** Standard `maxTilesPerMap` 1024 (4096²-Bloecke, 32 MiB), Obergrenze 4096.
  **C** Export liest jede Karte einzeln von der Platte ohne Cache (technisch, keine Spieleraenderung). Empfehlung **C** (+ A im Handbuch); B nur, wenn echte Server Speicherprobleme melden
  (B beschneidet die „endlos“-Zusage F6).
- **Q3 Web-Export neben Simple Livemap (BEW39) und `webExportDir` per Befehl (P3-8).** Kontext: zwei Web-Karten-Wege im Paket; der HTTP-Server ist der sicherheitsrelevanteste Code des Mods.
  Optionen: **A** Export bleibt (Standard aus, `autoOffWith` schaltet bei Dynmap/Bluemap/… ab), Doku verweist auf Livemap. **B** Export + HTTP-Server entfernen, Livemap uebernimmt.
  **C** zusammenlegen (Livemap liest die Wayfinder-Daten). Empfehlung **A** bis der Livemap-Dienst live ist, dann neu entscheiden; `webExportDir` bleibt per Befehl setzbar (Stufe 2 = Server-Admin), solange das Token-Gesetz aus P2-1 gilt.

## Urteil
**shipbar nach Fixes** (1 P1 gefixt, 2 P2 gefixt, 2 P2 offen als Rueckfrage, 11 P3 davon 2 gefixt, 1 TODO). Server-Autoritaet, Eingabepruefung und Kartentisch sind sorgfaeltig; der P1 war eine einzelne
Randwert-Luecke mit grossem Schaden (Absturz fremder Clients). Der HTTP-Server ist nach dem Token-Fix gut gehaertet; offene Punkte sind Speicherbedarf (Q2) und Bildkarten-Kosten (Q1).
